## 2. 構成の要点

- **Workers のカスタムドメインは、ゾーンが Cloudflare にないと使えない。** `triocareer.jp` のDNS は Xserver のまま
  なので、外部 DNS からの CNAME を受けられる **Pages** に載せる。加藤様の指摘（Workers はネームサーバー移管が必要）は正しい。
- Pages は静的配信だけ。フォームは Worker の `/api/inquiry` へクロスオリジンで POST する。
  Pages 側にバインディング（KV・シークレット）を入れる必要はない。
- 受信メールアドレスは **Make のシナリオにしか無い**。このリポジトリは公開なので、コードにも本書にも書かない。
- 放デイサイトは同じリポジトリの `afterschool/` 配下。保育園と CSS の構造を揃え、配色だけ変えている。

## 3. 放デイサイトの写真・PDF の入れ方（Drive 経由・CI）

バイナリをテキストのコミット API で入れると壊れる（保育園で 15,000 バイトに切り詰められた JPEG が本番に出た前歴）。
放デイの素材は **Google Drive から CI が取得する**。

- 元素材：Drive `放課後デイ／画像／{ロップ, コンパスマイル}`（ファイル ID と SHA-256 は `afterschool/tools/assets_manifest.json`）
- ワークフロー `.github/workflows/afterschool-build.yml`：
  `fetch_assets.py`（取得・SHA-256 照合）→ `process_assets.py`（WebP 化・引き伸ばしなし・完全デコード検証・PDF 配置）→ `build_site.py` → 参照チェック → コミット
- **前提 2 つ（ユーザー操作）**
  1. Drive の「画像」フォルダを「リンクを知っている全員（閲覧者）」にする（非公開だと Drive が HTML を返し、ハッシュ照合で止まる）
  2. ロップの室内写真（`lopp-room-sensory.png`, 617,611 バイト, SHA-256 `44bfb3f3…`）を `画像／ロップ` にアップロードし、
     その Drive ファイル ID を manifest の `"id": ""` に入れる
- **使わない素材**：`lopp-activity-1〜5.jpg`（顔に絵文字スタンプ入り）、`compass-google-entrance-detail.jpg` と
  `compass-google-entry-interior.jpg`（別事業者「ホエールリゾート」のサインが写っている。**別施設の写真は出さない**）
- 出力名は manifest の `output`。ページ側の参照名を変えるときは manifest と `build_site.py` の両方を直す。

## 4. Pages プロジェクトの作り方（Cloudflare ダッシュボード・ユーザー操作）

Workers & Pages → Create → **Pages** → Connect to Git → リポジトリ `t-ooku/trioland-social-publisher`。

| 項目 | 保育園 | 放デイ |
|---|---|---|
| Project name | `trioland-hoiku` | `trioland-afterschool` |
| Production branch | `main` | `main` |
| Framework preset | None | None |
| Build command | （空） | （空） |
| Build output directory | `site` | `site` |
| Root directory（Advanced） | `/`（空のまま） | `afterschool` |

作成すると `https://trioland-hoiku.pages.dev` / `https://trioland-afterschool.pages.dev` で見られる。
次に各プロジェクトの **Custom domains → Set up a custom domain** で
`hoiku.triocareer.jp` / `afterschool.triocareer.jp` を追加する。ゾーンが Cloudflare に無いので
「CNAME を追加してください」と出て、**CNAME 先は `<project>.pages.dev`** になる。これを加藤様に渡す。

加藤様への依頼文（プラン B・CNAME 2 本）：

```
hoiku.triocareer.jp       CNAME  trioland-hoiku.pages.dev
afterschool.triocareer.jp CNAME  trioland-afterschool.pages.dev
```

（Xserver の DNS 設定で、ホスト名 `hoiku` と `afterschool`、種別 CNAME、内容に上記の pages.dev を入れる。
TTL は既定でよい。）

- Pages のビルドは main への push ごとに走る。CI（GitHub Actions）が生成物をコミットするので、その push で Pages も更新される。
- Pages の「Deploy hooks」「環境変数」は不要。

## 6. Make（問い合わせ振り分け）

- シナリオ 6306695「トリオキャリアHP 問い合わせ振り分け（保育園・放デイ）」、Webhook 2823353、有効
- モジュール：`gateway:CustomWebHook` → `google-email:sendAnEmail`（v4。v2 は個人 Gmail だと「restricted scopes」で失敗する）
- Gmail 接続「大久津隆則's Gmail connection」は **2027-03-16 までに再認可**が必要
- 宛先は `to` の `switch(1.destination; …)`。放デイ 3 種は暫定で `baba@triocareer.jp`
- Free プランは月 1,000 オペレーション（1 件 = 2 オペレーション）
- Worker 側の Webhook URL は **ビルド変数 `INQUIRY_WEBHOOK_URL` ＋ デプロイコマンド
  `npx wrangler deploy --var INQUIRY_WEBHOOK_URL:$INQUIRY_WEBHOOK_URL`**。ダッシュボードにランタイムのシークレット欄が無いため
