# トリオランド採用SEO 運用方針（2026-10-18決定）

## 最優先の目的
求人SEO記事数ではなく、検索流入からの採用応募・面接・採用の増加。AI記事を毎日5本投稿する運用を終了する。

## 公開ゲート
- 毎日：既存ページと採用導線の品質点検・改善。新規記事公開は必須ではない。
- 新規記事：原則週1〜2本以下。既存記事にない検索意図、独自の事実・実例、求職者の意思決定に役立つ情報、最新の公式募集条件、内部リンクと応募CTAが揃う場合だけ公開する。
- 不明な給与・勤務地・手当・職員体制・研修・待遇・採用実績・職員の声を創作しない。募集条件の正式な改訂額は権限ある資料で確定するまで変更しない。
- 記事が「公式採用情報では確認できません」の繰り返しだけになる場合は新規公開せず、既存ページを改善する。
- 同じキーワード・検索意図を狙う既存ページがあれば統合候補にする。検索実績を見ずに一括削除・301リダイレクト・canonical変更を行わない。
- GitHub mainコミットと本番HTTP 200を区別し、未確認を公開確認済みと報告しない。

## 日次点検
1. 公式採用ページと自サイトの募集条件の矛盾、特に最低賃金未満の古い時給表示を確認する。
2. site/recruit/*.html、site/recruit/index.html、site/sitemap.xml、canonical、応募CTAを点検。
3. 重複クラスタの改善候補を選び、必要なら既存記事をリライト。検索意図の分散と事実確認を徹底。
4. Search Console/GA4/応募フォームの接続がある場合は、期間付きで表示回数・クリック・CTR・応募CTAクリック・応募完了を確認。未接続は「未取得」。
5. 変更があればテスト→main→CI→本番URL→応募導線の順に検証。障害時は安全な再試行と原因記録。

## 初期監査（GitHub main 2026-10-18）
- site/recruit/ に HTML 122件（index.html含む）、記事121件を確認。
- 既存記事の重複候補：調理職のアレルギー・衛生記録、資格要件・経験者優遇、保育補助の1日の流れ・入職初日。
- これはタイトル・一部本文に基づく候補であり、検索カニバリの確定ではない。Search Console実データ、被リンク、検索流入を確認してから統合判断する。
- 採用条件の重要課題：公式ページに古い時給表示の可能性。実支給額不明のため新金額を推測せず、正式額を確認する。

## 役割分担
- ChatGPT：戦略、監査、優先順位、実行調整、結果検証。
- Claude Cowork：応募者視点の文章・UI/UX、重複候補の統合案、応募導線の改善案。未確認事実は掲載しない。
- Codex：コード、SEO設定、計測、CI、公開・本番検証。
- Coworkへの指示ファイルのGitHub保存は「指示書保存」であり、Coworkが受領・実行したことを意味しない。
